01 · Overview

接入总览

抓拍兼容模式组件是 Android 原生 View。传统 uni-app 的普通 .vue 页面由 WebView 渲染，无法直接承载它；App 端的 .nvue 页面使用原生渲染，可以正常内嵌。

02 · Prerequisites

前置条件

  • 目标项目是传统 uni-app（Vue2 或 Vue3），运行目标为 App-Android。
  • 使用 HBuilderX 4.31 或更高版本；插件元数据声明传统 uni-app 编译器版本为 4.52 或更高。
  • 当前插件版本为 2026.09.08。
  • 当前 utssdk/app-android/config.json 实际设置 minSdkVersion: 23，因此按 Android 6.0+ 准备。
  • 设备或模拟器使用 arm64-v8a / armeabi-v7a；如用模拟器，优先选 ARM 镜像。
  • 必须制作自定义调试基座；标准基座不包含插件的第三方 SDK、CameraX 依赖和原生资源。
组件无需手动 import 或 components 注册。 兼容模式 UTS 组件会全局注册，页面里直接使用组件标签即可。
03 · Integration

接入步骤

1

把完整插件复制到目标工程

将本仓库的整个 uni_modules/FaceAI-Search 目录复制到第三方项目的 uni_modules 下，不要只复制组件入口文件。

目标工程目录
your-uniapp-project/
├─ pages/
├─ uni_modules/
│  └─ FaceAI-Search/
│     ├─ package.json
│     ├─ components/
│     └─ utssdk/
│        └─ app-android/
│           ├─ index.vue              # 抓拍兼容模式组件入口
│           ├─ CaptureFaceNativeView.kt
│           ├─ config.json
│           ├─ AndroidManifest.xml
│           └─ ...
├─ manifest.json
└─ pages.json

插件的依赖、原生源码、Manifest、资源和 AAR 必须一起参与基座打包。

2

检查传统 uni-app 的 Android 配置

推荐在 HBuilderX 的 manifest.json 可视化界面中设置最低 Android 版本和 CPU 类型。若使用源码视图，传统 uni-app 的配置位于 app-plus.distribute.android。

manifest.json · 合并到现有配置，不要整段覆盖
{
  "app-plus": {
    "distribute": {
      "android": {
        "minSdkVersion": 23,
        "abiFilters": [
          "armeabi-v7a",
          "arm64-v8a"
        ],
        "permissions": [
          "<uses-permission android:name=\"android.permission.CAMERA\"/>"
        ]
      }
    }
  }
}
插件自己的 AndroidManifest.xml 已声明相机权限，打包时会合并。目标工程中再次显式声明，便于第三方团队审查和维护；如果现有配置已包含该权限，不需要重复添加。
3

新增并注册 .nvue 抓拍页面

新建 pages/face-capture/face-capture.nvue，然后在 pages.json 注册路由。路由不写文件扩展名。

pages.json · pages 数组新增一项
{
  "path": "pages/face-capture/face-capture",
  "style": {
    "navigationBarTitleText": "人脸抓拍",
    "navigationBarBackgroundColor": "#10243d",
    "navigationBarTextStyle": "white"
  }
}
如果同一路径同时存在 face-capture.vue 和 face-capture.nvue，App 端会优先使用 .nvue；为减少维护歧义，建议抓拍页只保留 .nvue。
4

在 .nvue 页面放置组件

组件必须设置明确宽高，否则原生 View 可能不显示。最小可运行结构如下；生产项目建议直接使用下一章的完整示例。

pages/face-capture/face-capture.nvue · 最小结构
<template>
  <view class="page">
    <face-ai-capture-compat
      ref="captureCompat"
      :performanceMode="1"
      :needLivenessCheck="false"
      :cameraId="0"
      :linearZoom="0.01"
      :rotationDegrees="-1"
      :showFaceCover="true"
      :showFaceCoverTips="true"
      :autoStart="true"
      style="width: 750rpx; height: 900rpx; background-color: #000000;"
      @ready="onCaptureReady"
      @result="onCaptureResult"
      @tips="onCaptureTips"
      @error="onCaptureError"
      @camera-change="onCameraChange"
    />
  </view>
</template>

<script>
export default {
  methods: {
    onCaptureReady() {},
    onCaptureResult(payload) { console.log(payload) },
    onCaptureTips(payload) { console.log(payload) },
    onCaptureError(payload) { console.error(payload) },
    onCameraChange(payload) { console.log(payload) }
  }
}
</script>
5

从业务 .vue 页面跳转

普通业务页只负责路由，不直接放置原生组件。

任意业务页面
<button @click="openFaceCapture">开始人脸抓拍</button>

<script>
export default {
  methods: {
    openFaceCapture() {
      uni.navigateTo({
        url: '/pages/face-capture/face-capture'
      })
    }
  }
}
</script>

抓拍结果如需回传业务页，可按现有项目约定使用 eventChannel、Pinia/Vuex 或页面事件；不要把大段 Base64 长期存进全局响应式状态。

6

制作并使用自定义调试基座

  1. HBuilderX 顶部选择：运行 → 运行到手机或模拟器 → 制作自定义调试基座。
  2. 选择 Android，确认应用信息并提交云端打包。
  3. 完成后选择：运行 → 运行到手机或模拟器 → 运行到 Android App 基座。
  4. 在运行窗口明确选择使用自定义基座运行，再选择设备。
仅“制作过”还不够。每次运行时仍要选中自定义基座；误用标准基座时，常见表现是插件不存在、原生依赖缺失或组件空白。

更新插件版本、CameraX/第三方 SDK、原生资源、AndroidManifest.xml 或 config.json 后，需要重新制作基座。只改页面样式和普通 JS 逻辑，通常无需重做。

04 · Copy-ready Sample

完整 .nvue 示例

下面示例包含运行时相机权限、授权拒绝后的设置入口、结果展示、再次抓拍和前后摄像头切换，可直接作为第三方项目的起点。

pages/face-capture/face-capture.nvue
<template>
  <view class="page">
    <view v-if="cameraGranted" class="capture-page">
      <face-ai-capture-compat
        ref="captureCompat"
        :performanceMode="1"
        :needLivenessCheck="false"
        :cameraId="0"
        :linearZoom="0.01"
        :rotationDegrees="-1"
        :showFaceCover="true"
        :showFaceCoverTips="true"
        :autoStart="true"
        style="width: 750rpx; height: 850rpx; background-color: #000000;"
        @ready="onCaptureReady"
        @result="onCaptureResult"
        @tips="onCaptureTips"
        @error="onCaptureError"
        @camera-change="onCameraChange"
      />

      <text class="status">{{ statusText }}</text>
      <text class="status">抓拍次数：{{ captureCount }}</text>
      <text class="status">静默活体分数：{{ silentScore }}</text>

      <view class="image-row">
        <image class="result-image" mode="aspectFit" :src="croppedImageSrc" />
        <image class="result-image image-last" mode="aspectFit" :src="originImageSrc" />
      </view>

      <view class="button-row">
        <button class="button primary" :disabled="!ready || capturing" @tap="retryCapture">
          {{ capturing ? '抓拍中…' : '再次抓拍' }}
        </button>
        <button class="button secondary" :disabled="!ready" @tap="toggleCamera">
          切换相机
        </button>
      </view>
    </view>

    <view v-else class="permission-page">
      <text class="permission-title">需要相机权限</text>
      <text class="permission-text">相机仅用于本地人脸抓拍，请先授权。</text>
      <button class="button primary permission-button" :disabled="permissionRequesting" @tap="requestCameraPermission">
        {{ permissionRequesting ? '正在申请…' : '授权相机' }}
      </button>
      <button v-if="permissionPermanentlyDenied" class="button secondary permission-button" @tap="openPermissionSettings">
        打开系统设置
      </button>
      <text class="permission-text">{{ statusText }}</text>
    </view>
  </view>
</template>

<script>
const CAMERA_PERMISSION = 'android.permission.CAMERA'

export default {
  data() {
    return {
      pageReady: false,
      cameraGranted: false,
      permissionRequesting: false,
      permissionPermanentlyDenied: false,
      ready: false,
      capturing: false,
      captureCount: 0,
      silentScore: 0,
      currentCameraId: 0,
      croppedImageSrc: '',
      originImageSrc: '',
      statusText: '正在检查相机权限…'
    }
  },

  onReady() {
    this.pageReady = true
    this.requestCameraPermission()
  },

  onShow() {
    // 从系统设置返回时重新检查；首次 onShow 发生在 onReady 前，需跳过。
    if (this.pageReady && !this.cameraGranted && !this.permissionRequesting) {
      this.requestCameraPermission()
    }
  },

  onUnload() {
    const capture = this.$refs.captureCompat
    if (capture) capture.stop()
  },

  methods: {
    requestCameraPermission() {
      if (this.permissionRequesting) return
      this.permissionRequesting = true
      this.statusText = '等待相机权限授权结果…'

      plus.android.requestPermissions(
        [CAMERA_PERMISSION],
        (result) => {
          this.permissionRequesting = false
          const deniedPresent = result.deniedPresent || []
          const deniedAlways = result.deniedAlways || []

          if (deniedPresent.length === 0 && deniedAlways.length === 0) {
            this.cameraGranted = true
            this.permissionPermanentlyDenied = false
            this.statusText = '权限已授予，正在加载相机…'
            return
          }

          this.cameraGranted = false
          this.permissionPermanentlyDenied = deniedAlways.length > 0
          this.statusText = this.permissionPermanentlyDenied
            ? '相机权限已被永久拒绝，请到系统设置中开启'
            : '相机权限未授予，可再次申请'
        },
        (error) => {
          this.permissionRequesting = false
          this.cameraGranted = false
          this.statusText = '权限申请失败：' + (error.message || error.code || '未知错误')
        }
      )
    },

    openPermissionSettings() {
      uni.openAppAuthorizeSetting()
    },

    // 同时兼容 JS 对象、event.detail 和 Map 形态的事件参数。
    readField(payload, key) {
      const source = payload && payload.detail ? payload.detail : payload
      if (!source) return undefined
      if (typeof source.get === 'function') return source.get(key)
      return source[key]
    },

    toImageSource(base64) {
      if (!base64 || base64.indexOf('data:image/') === 0) return base64 || ''
      return 'data:image/jpeg;base64,' + base64
    },

    onCaptureReady() {
      this.ready = true
      this.capturing = true
      this.statusText = '抓拍组件已启动，请将人脸置于取景区域'
    },

    onCaptureResult(payload) {
      const croppedBase64 = this.readField(payload, 'croppedBase64') || ''
      const originBase64 = this.readField(payload, 'originBase64') || ''

      this.captureCount += 1
      this.silentScore = Number(this.readField(payload, 'silentScore') || 0)
      this.croppedImageSrc = this.toImageSource(croppedBase64)
      this.originImageSrc = this.toImageSource(originBase64)
      this.capturing = false
      this.statusText = '本轮完成；需要继续时点击“再次抓拍”'
    },

    onCaptureTips(payload) {
      const code = this.readField(payload, 'code')
      const message = this.readField(payload, 'message') || ''
      this.statusText = '提示 ' + code + '：' + message
    },

    onCaptureError(payload) {
      const code = this.readField(payload, 'code') || 'UNKNOWN'
      const message = this.readField(payload, 'message') || ''
      this.statusText = '错误 ' + code + '：' + message
      this.capturing = false

      if (code === 'CAMERA_PERMISSION_REQUIRED') {
        this.cameraGranted = false
      }
    },

    onCameraChange(payload) {
      this.currentCameraId = Number(this.readField(payload, 'cameraId') || 0)
      this.statusText = this.currentCameraId === 0 ? '已切换到前置相机' : '已切换到后置相机'
    },

    retryCapture() {
      const capture = this.$refs.captureCompat
      if (!capture || !this.ready || this.capturing) return
      capture.retry()
      this.capturing = true
      this.statusText = '正在等待下一次抓拍…'
    },

    toggleCamera() {
      const capture = this.$refs.captureCompat
      if (!capture || !this.ready) return
      capture.toggleCamera()
      this.statusText = '正在切换相机…'
    }
  }
}
</script>

05 · Component API

组件属性、事件与方法

属性

属性类型 / 默认值说明建议
performanceModeNumber / 1-1 无限制、0 简单、1 快速、2 精确。默认 1
needLivenessCheckBoolean / false是否计算静默活体分数，抓拍组件默认关闭。需要时显式开启
cameraIdNumber / 00 前置，1 后置；启动时不存在会尝试降级到可用摄像头。自拍默认 0
linearZoomNumber / 0.01线性变焦，原生层会限制到 0–1；不建议传入过大的值。先保持默认
rotationDegreesNumber / -1-1 跟随显示方向；也可固定为 0/90/180/270。推荐 -1
showFaceCoverBoolean / true只控制原生圆形人脸引导遮罩，不控制提示文字；兼容模式组件预览固定使用 FILL_CENTER。默认显示
showFaceCoverTipsBoolean / false独立控制原生过程提示文字；显示时圆框使用短边 1/13 边距，文字位于圆框上方并间隔 5dp；隐藏时圆框边距为 4dp。按 UI 需求开启
autoStartBoolean / true组件载入后自动调用 start()。权限通过后再挂载组件

事件

事件参数触发时机
ready无原生 View 已创建，可以调用实例方法。
resultcroppedBase64、silentScore、originBase64完成一轮有效人脸抓拍后触发；组件随后暂停检测。
tipscode、message人脸过近、过远、偏转、未检测到人脸等过程提示。
errorcode、message权限、相机绑定、预览、帧处理或编码发生异常。
camera-changecameraId实际摄像头发生切换，或启动时自动降级到另一摄像头。

result 数据

字段类型含义
croppedBase64String检测、矫正并裁剪后的 224×224 人脸 JPEG Base64。
silentScoreNumber静默活体分数；关闭活体计算时不应用作判断依据。
originBase64String本次检测使用的相机原图 JPEG Base64。

实例方法

方法说明传统 nvue 用法
start()按当前属性开始或重启一次抓拍会话。this.$refs.captureCompat.start()
stop()停止相机和帧分析。页面卸载前可调用
retry()一次结果返回后开始下一轮抓拍。连续业务必用
switchCamera(id)切到指定摄像头，0 前置、1 后置。监听 camera-change
toggleCamera()在前后摄像头之间切换。处理 CAMERA_SWITCH_FAILED
canSwitchCamera()原生侧提供同步布尔返回值。nvue 不应依赖同步返回值
受 nvue / Weex 桥接限制，兼容模式组件的同步方法返回值不可靠。因此传统 uni-app 页面不要依赖 canSwitchCamera() 的返回值；直接调用切换方法，再以 camera-change 或 error 事件确认结果。

推荐控制原则

  • 先拿到相机权限，再通过 v-if 挂载组件，避免 autoStart 立即触发权限错误。
  • ready 之前不要调用实例方法。
  • 每次 result 后原生检测会暂停；业务处理完成后显式调用 retry()。
  • 防止连续点击：调用 retry() 后将按钮置为处理中，收到 result 或 error 再恢复。
  • 页面卸载时调用 stop()；组件销毁时插件内部还会执行 release()。
  • Base64 体积较大，展示或提交完成后及时清空；不要写入日志、URL 或长期缓存。

常见错误码

错误码含义 / 处理方向
CAMERA_PERMISSION_REQUIRED相机权限缺失；隐藏组件并重新申请或引导到系统设置。
INVALID_CAMERA_IDcameraId 只能是 0 或 1。
INVALID_ROTATION_DEGREES仅允许 -1、0、90、180、270。
CAMERA_NOT_AVAILABLE设备没有请求的前置/后置摄像头。
CAMERA_DEPENDENCY_CONFLICT目标工程中 CameraX 二进制依赖存在版本冲突，检查其他相机插件。
CAMERA_BIND_FAILED相机绑定失败；检查权限、生命周期、相机占用和依赖。
CAMERA_SWITCH_FAILED切换相机失败；保持当前摄像头并提示用户。
CAMERA_PREVIEW_NOT_STREAMING相机已打开但预览未出流；插件会先自动尝试兼容预览模式。
FRAME_PROCESS_FAILED相机帧处理异常。
BITMAP_ENCODE_FAILED结果图片转 Base64 失败；允许用户重新抓拍。
CAPTURE_RETRY_FAILED下一轮抓拍状态重置失败，可停止后重新 start()。
VIEW_RELEASED组件已经释放，不应继续调用实例方法。
07 · Troubleshooting

常见问题排查

页面能打开，但组件完全不显示
  1. 确认文件后缀是 .nvue，不是普通 .vue。
  2. 确认组件写了明确的 width 和 height。
  3. 确认插件目录完整，组件标签拼写为 face-ai-capture-compat。
  4. 确认当前运行的是自定义基座。
组件显示黑屏或相机不出画面

先检查相机权限、其他页面/SDK 是否占用相机、设备是否有可用摄像头。插件检测到预览未开始时会自动从 Performance 预览切到 Compatible 预览；仍失败会回调 CAMERA_PREVIEW_NOT_STREAMING。

只回调一次 result，后面不再抓拍

这是设计行为。嵌入组件每次成功后暂停检测，业务处理完本次结果后调用 this.$refs.captureCompat.retry() 开启下一轮。

result 里的字段读取不到

兼容模式事件跨 UTS / JS 桥接后，参数可能表现为普通对象、event.detail 或带 get() 的 Map。使用完整示例里的 readField() 统一读取。

云打包提示 UniNativeViewElement 或 Theme.FaceAISDK.Fullscreen 找不到

这是插件 2026.09.07 的传统 uni-app 编译兼容问题，不是业务页面错误。请更新到 2026.09.08 或更高版本，清理构建缓存后重新制作自定义基座。新版已用 UNI-APP-X 条件编译隔离标准模式桥接类，并把全屏 Activity 主题放入插件自身资源。

自定义基座编译时出现 CameraX 冲突

检查目标工程中其他相机、扫码、人脸插件是否重复声明不同版本的 androidx.camera。当前插件配置使用 CameraX 1.5.2；统一依赖版本后重新制作基座。

模拟器无法运行或找不到原生库

插件配置支持 armeabi-v7a 和 arm64-v8a。不要使用仅 x86/x86_64 的模拟器镜像，优先使用 Android 真机或 ARM 模拟器。

从系统设置返回后仍没有启动相机

在页面 onShow 中重新检查/申请权限，权限成功后再令 cameraGranted = true，由 v-if 重新挂载组件。完整示例已包含该处理。

上线前验收清单

  • 退出页面后相机被释放，再次进入仍能正常启动。
