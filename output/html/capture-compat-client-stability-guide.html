一、必须遵守的 10 条规则

  • 抓拍页面必须使用 .nvue，并给组件设置明确、非零的宽高。
  • 一个页面只允许挂载一个抓拍组件，禁止隐藏着第二个实例。
  • 先取得相机权限，再通过 v-if 挂载组件。
  • autoStart=true 时，禁止在 ready 回调里再次调用 start()。
  • 首次结果之后，下一轮调用 retry()，不要重复调用 start()。
  • 重试和切换相机必须加按钮锁，等待结果事件后才能再次点击。
  • 页面卸载时调用 stop()，不要用延时器在卸载后重新启动。
  • 进入抓拍页前，先停止扫码、录像或其他占用相机的插件。
  • 禁止完整打印、深拷贝或长期保存结果中的两张 Base64 图片。
  • 收到错误时按错误码处理，禁止用无限定时重启掩盖错误。
高风险写法：setInterval(() => capture.start(), 1000)、在多个 watch 中调用 start()、连续点击 toggleCamera()、console.log(result)。这些写法可能造成相机反复绑定、主线程拥塞或内存快速增长。

二、正确的调用生命周期

阶段接入方动作禁止事项
进入页面检查并申请 CAMERA 权限；成功后再挂载组件。权限未知时直接创建并反复重建组件。
readyautoStart=true 时只更新 UI 状态，等待相机启动。再次调用 start()。
tips只更新短提示文字。在每次提示中发请求、重建页面或切换相机。
result处理本轮结果，解除抓拍锁；需要下一轮时由用户触发 retry()。在回调中立即递归调用 start()。
切换相机设置 cameraSwitching=true；收到 camera-change 或 error 后解除。切换完成前再次调用切换方法。
退出页面调用一次 stop()；组件销毁时插件会完成最终释放。保留定时器、异步回调再次调用组件。
如果使用 autoStart=false，应在权限通过且收到 ready 后只调用一次 start()。参数变化时优先调用对应方法，例如切换镜头使用 switchCamera(0/1)。

三、推荐的 .nvue 接入写法

下面只展示防重入和生命周期相关代码。事件参数可能是普通对象、event.detail 或 Map，因此统一通过 readField() 读取。

pages/face-capture/face-capture.nvue
<template>
  <view class="page">
    <face-ai-capture-compat
      v-if="cameraGranted"
      ref="captureCompat"
      :needLivenessCheck="false"
      :cameraId="0"
      :linearZoom="0.01"
      :showFaceCover="true"
      :showFaceCoverTips="true"
      :autoStart="true"
      style="width: 750rpx; height: 900rpx; background-color: #000;"
      @ready="onCaptureReady"
      @result="onCaptureResult"
      @tips="onCaptureTips"
      @error="onCaptureError"
      @camera-change="onCameraChange"
    />

    <button :disabled="!ready || capturing" @tap="retryCapture">
      {{ capturing ? '抓拍中…' : '再次抓拍' }}
    </button>
    <button :disabled="!ready || cameraSwitching" @tap="toggleCamera">
      {{ cameraSwitching ? '切换中…' : '切换相机' }}
    </button>
  </view>
</template>

<script>
export default {
  data() {
    return {
      cameraGranted: false,
      ready: false,
      capturing: false,
      cameraSwitching: false,
      statusText: ''
    }
  },

  onUnload() {
    const capture = this.$refs.captureCompat
    if (capture) capture.stop()
    this.ready = false
    this.capturing = false
    this.cameraSwitching = false
  },

  methods: {
    readField(payload, key) {
      const source = payload && payload.detail ? payload.detail : payload
      if (!source) return undefined
      if (typeof source.get === 'function') return source.get(key)
      return source[key]
    },

    onCaptureReady() {
      // autoStart=true：这里不要再调用 start()。
      this.ready = true
      this.capturing = true
      this.statusText = '相机启动中…'
    },

    onCaptureResult(payload) {
      const croppedBase64 = this.readField(payload, 'croppedBase64') || ''
      const originBase64 = this.readField(payload, 'originBase64') || ''
      const silentScore = Number(this.readField(payload, 'silentScore') || 0)

      this.capturing = false
      this.statusText = '本轮抓拍完成'

      // 交给业务方法立即展示或提交；禁止 console.log(payload)。
      this.handleCaptureResult(croppedBase64, originBase64, silentScore)
    },

    onCaptureTips(payload) {
      this.statusText = this.readField(payload, 'message') || ''
    },

    onCameraChange(payload) {
      this.cameraSwitching = false
      const cameraId = Number(this.readField(payload, 'cameraId') || 0)
      this.statusText = cameraId === 0 ? '当前为前置相机' : '当前为后置相机'
    },

    onCaptureError(payload) {
      const code = this.readField(payload, 'code') || 'UNKNOWN'
      const message = this.readField(payload, 'message') || ''
      this.cameraSwitching = false
      this.statusText = code + '：' + message

      // 单帧异常由组件自动跳过或复位，不要销毁重建。
      if (code === 'FRAME_PROCESS_FAILED' || code === 'FRAME_PROCESS_TIMEOUT') {
        this.capturing = true
        return
      }

      // 切换失败时原相机仍可能可用。
      if (code === 'CAMERA_NOT_AVAILABLE' || code === 'CAMERA_SWITCH_FAILED') {
        return
      }

      this.capturing = false
      if (code === 'CAMERA_PERMISSION_REQUIRED') this.cameraGranted = false
    },

    retryCapture() {
      const capture = this.$refs.captureCompat
      if (!capture || !this.ready || this.capturing) return
      this.capturing = true
      capture.retry()
    },

    toggleCamera() {
      const capture = this.$refs.captureCompat
      if (!capture || !this.ready || this.cameraSwitching) return
      this.cameraSwitching = true
      capture.toggleCamera()
    },

    handleCaptureResult(croppedBase64, originBase64, silentScore) {
      // 由业务方实现。使用完成后及时解除对 Base64 字符串的引用。
    }
  }
}
</script>
结果包含裁剪图和相机原图两段 Base64。不要把整个 payload 写入日志、URL、长生命周期全局状态或重复 JSON 序列化；这些操作通常比相机检测本身更容易造成页面卡顿和内存峰值。

四、错误码处理原则

错误码级别接入方处理
FRAME_PROCESS_FAILED可恢复组件会继续处理后续帧，保持页面和组件，不要重建。
FRAME_PROCESS_TIMEOUT可恢复组件已自动复位检测状态；记录设备型号和错误即可。
CAMERA_NOT_AVAILABLE切换失败提示设备没有目标镜头，解除切换按钮锁。
CAMERA_SWITCH_FAILED切换失败保持当前镜头，解除切换按钮锁，不要连续重试。
BITMAP_ENCODE_FAILED本轮失败允许用户再次调用 retry()。
CAMERA_PERMISSION_REQUIRED需停止隐藏组件，重新申请权限或引导用户进入系统设置。
CAMERA_BIND_FAILED需停止检查是否有其他相机插件占用、页面生命周期和依赖版本。
CAMERA_PREVIEW_NOT_STREAMING需停止预览兼容降级仍失败；不要使用无限定时器反复启动。
CAPTURE_SESSION_REPLACED重复实例另一个抓拍组件接管了相机，检查重复挂载。
SDK_INIT_FAILED初始化失败记录完整错误文本，停止当前会话，允许用户手动重新进入页面。

五、出现“卡死”时如何判断

  1. 按钮、滚动和返回手势全部无响应：属于 UI 主线程阻塞。首先检查是否打印完整 Base64、同步上传、频繁 JSON 序列化，或者循环创建/销毁组件。
  2. 页面仍可点击，但预览黑屏：通常是权限、相机被占用、生命周期或 CameraX 绑定问题。查看 error 事件。
  3. 预览正常、提示还在变化，但没有第二次结果：检查上一轮结果后是否调用了 retry()。
  4. 切换相机后短暂停顿：等待 camera-change 或 error，不要连续点击，也不要定时重复切换。
  5. 频繁进出页面后才出现：检查页面卸载是否调用 stop()，以及是否存在未清理的定时器或第二个相机组件。
排查时请保留：手机品牌与型号、Android 版本、发生时间、最近一次错误码、是否刚切换相机、是否存在扫码/录像插件。不要提交包含完整人脸 Base64 的日志。

六、交付前稳定性验收清单

  1. 首次授权、拒绝授权、永久拒绝、从系统设置返回四条路径均测试通过。
  2. 连续完成至少 50 次 result → retry，页面响应正常，内存没有持续上升。
  3. 连续切换前后摄像头 20 次，按钮不会连点，均收到 camera-change 或 error。
  4. 连续进入和退出抓拍页面 50 次，再次进入仍可正常打开相机。
  5. 抓拍期间切到后台再返回，页面不会保留不可用的黑屏实例。
  6. 进入抓拍页前启动过扫码或其他相机功能时，已确认前一个相机会话完全停止。
  7. 业务代码中不存在 console.log(result)、循环 start() 或无限自动重启逻辑。
  8. Base64 使用完成后会清空，不会长期存入 Pinia、Vuex、本地缓存或页面历史。
  9. 在至少一台低内存设备和客户主要目标机型上完成真机测试。
